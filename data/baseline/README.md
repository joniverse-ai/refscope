# 베이스라인 측정 — PoC를 만들기 **전에** 해야 하는 일

> 이 폴더는 사람이 채운다. 자동화 도구가 건드리지 않는다.

## 왜 지금인가

두 가지 이유로, PoC 결과물을 보기 **전에** 해야 한다.

1. **시간**: 도구가 생긴 뒤에는 "예전에 얼마나 걸렸더라"를 정직하게 재현할 수 없다.
2. **정답 라벨**: PoC 출력을 먼저 보면 그것에 끌려간다(앵커링). 내가 손으로 뽑은 카피와 색이 정답 노릇을 하려면, 도구 출력을 보지 않은 상태에서 만들어야 한다.

## 무엇을 하나

상세페이지 **3개**를 평소 하던 대로 손으로 정리한다. (최소 2개, 3개면 충분)

권장 대상 — 길이가 서로 달라 비교가 된다:

| id | 브랜드 | 높이 |
|---|---|---|
| `gyodong_manwol` | 교동한과 만월 | 17,275px |
| `hanpoom_99flower` | 한품 99플라워 | 12,868px |
| `hangamall_dao` | 강릉명일한과 한과다오 | 44,491px |

## 어떻게 하나

1. `template.md`를 `<id>.md`로 복사한다. (예: `gyodong_manwol.md`)
2. **스톱워치를 켜고** 브라우저에서 해당 URL을 연다. URL은 `data/refs.yaml`에 있다.
3. 평소 리서치하듯 정리한다 — 카피 옮겨 적기, 색 찍기, 섹션 순서 적기.
4. 끝나면 스톱워치를 멈추고 소요 시간을 적는다.
5. **다음 사이트로 넘어가기 전에** 파일을 저장한다.

### 규칙

- 페이지 전체를 완벽히 옮길 필요 없다. **평소 리서치하는 만큼만** 한다. 그게 진짜 베이스라인이다.
- 중간에 멈췄다면 멈춘 시간을 빼고 순수 작업 시간만 적는다.
- 힘들면 힘들다고 메모에 적는다. 그 메모가 검증 문서의 정성 재료가 된다.

## 이 데이터가 나중에 어디에 쓰이나

| 여기서 적은 것 | 검증 문서에서 |
|---|---|
| 소요 시간 | 성공 기준 #1 (사이트당 3분 이내) 비교 대상 |
| 헤드라인·서브카피 | 성공 기준 #2 (카피 추출 재현율 80%) 의 정답 |
| 브랜드 컬러 3색 | 성공 기준 #3 (자동 팔레트 top-8 안에 2색) 의 정답 |
| 섹션 순서 | 성공 기준 #4 (섹션 분류 정확도 70%) 의 정답 |
| 메모·불편함 | 정성 비교의 재료 |
