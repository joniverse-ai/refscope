## 0. 검증이 정직하기 위한 조건

베이스라인은 **PoC 결과물을 보기 전에** 측정했다. 두 가지 이유에서다.

1. 도구가 생긴 뒤에는 "예전에 얼마나 걸렸더라"를 정직하게 재현할 수 없다.
2. PoC 출력을 먼저 보면 정답 라벨이 거기에 끌려간다(앵커링).

사용자(박정목)가 2026-08-12에 상세페이지 3개를 평소 하던 대로 손으로 정리하며
스톱워치를 쟀다. 그때 적은 카피·컬러·섹션이 그대로 정답이 된다. → [`data/baseline/`](../data/baseline/)

| 사이트 | 페이지 높이 | 소요 | 적은 카피 |
|---|---|---|---|
| 교동한과 만월 | 17,275px | 17분 | 7줄 |
| 한품 99플라워 | 12,868px | 10분 | 3줄 |
| 강릉명일한과 한과다오 | 44,491px | 16분 | 3줄 |
| **합계** | **74,634px** | **43분** | **13줄** |

### 베이스라인에서 이미 드러난 것

여기서 예상하지 못한 게 하나 나왔다. **가장 긴 페이지에서 가장 적게 적었다.**

| 사이트 | 분당 훑은 픽셀 | 적은 카피 |
|---|---|---|
| 한품 (12,868px) | 1,287px/분 | 3줄 |
| 교동한과 (17,275px) | 1,016px/분 | 7줄 |
| 강릉명일한과 (44,491px) | **2,781px/분** | 3줄 |

44,491px 페이지에서는 2.7배 빠르게 훑었다. **꼼꼼히 본 게 아니라 포기한 것이다.**
사용자가 남긴 메모가 이를 뒷받침한다.

> "시간이 너무 오래 걸리고 휴먼에러가 발생하지 않을까 걱정이 됩니다."

즉 기존 방식의 진짜 문제는 느린 것만이 아니라 **길수록 품질이 떨어진다**는 것이다.
이 점이 뒤의 비교에서 중요해진다.

## 1. 정량 비교 — A / B / C

문제 정의서 6절이 약속한 세 비교군이다.

- **A 수작업** — 사람이 손으로 정리 (기존 방식)
- **B 순진한 AI** — 페이지를 VLM에 통째로 던지고 "리서치 노트로 정리해줘"
- **C refscope** — 구간을 판정하고 도구를 갈아 끼운 파이프라인

**B와 C는 같은 모델(qwen2.5vl:7b)로 같은 페이지를 본다.** 다른 것은 무엇을 어떻게
보여주고 무엇을 시키느냐뿐이다. 그래서 B와 C의 차이는 곧 **설계가 만든 차이**다.

```bash
uv run python -m refscope.compare_abc
```

| 비교군 | 소요 | 카피 | 재현율 | 근거율 | 컬러 |
|---|---|---|---|---|---|
| A 수작업 | 2,580s (43분) | 13줄 | 100%* | 100% | 9/9 |
| B 순진한 AI | **75s** | 20줄 | 38% | **61%** | **3/9** |
| **C refscope** | **58~78s** | **75줄** | **84%** | **100%** | **6/9** |

<sub>* A의 재현율 100%는 정의상 그렇다 — A가 정답이기 때문이다.</sub>
<sub><br>† C의 소요는 실행마다 58~78초로 흔들린다. Ollama 모델이 메모리에 이미 올라와 있으면
빠르고, 새로 올리면 느리다. B도 같은 조건을 받으므로 비교 자체는 공정하다.
아래 본문은 보수적으로 78초 기준으로 읽는다.</sub>

- **재현율** — 사람이 적어둔 카피를 잡았는가. B는 최대 10줄을 요구받았으므로
  C도 상위 10줄로 맞춰 재면 63%, 보유한 75줄 전체 기준으로는 84%다.
- **근거율** — 뱉은 카피가 실제로 페이지에 박혀 있는 글자인가. (문자 5-gram이
  DOM+OCR 텍스트에 실재하는지로 판정)
- **컬러** — 사람이 스포이드로 찍은 3색 중 CIEDE2000 ΔE≤10으로 맞춘 수.

### 읽는 법

**B와 C는 거의 같은 시간을 쓴다 (75초 vs 78초).** 그런데:

- **B가 뱉은 카피의 39%는 페이지에 없는 문장이다.** 지어냈다.
- **B의 컬러는 3/9.** `#FFD700`, `#8B4513`, `#ADD8E6` — CSS 상투색을 추측했다.
- **B는 프롬프트 문장을 카피로 되뱉은 것이 2건 있었다.**
- C는 근거율 100%다. 내놓은 것은 전부 페이지에 실재하는 글자다.

> 순진한 방법은 **빠르고, 자신 있고, 틀린다.** 이게 가장 위험한 조합이다.
> 리서치 노트는 나중에 검증되지 않고 그대로 회의 자료가 되기 때문이다.

### 성공 기준 대조

| # | 지표 | 목표 | 결과 | |
|---|---|---|---|---|
| 1 | 사이트 1개 정리 시간 | 3분 이내 | **23~30초** | ✅ |
| 2 | 카피 추출 재현율 | 80% 이상 | **84%** | ✅ |
| 3 | 브랜드 컬러 재현 | 3색 중 2색 이상 | **3개 사이트 모두 2/3** | ✅ |
| 4 | 섹션 구조 분류 정확도 | 70% 이상 | **47%** | ❌ |
| 5 | 전체 리서치 소요 (10개+) | 15분 이내 | **3.4~4.8분** (12개) | ✅ |

**5개 중 4개 달성, 1개 미달.** 미달한 4번은 아래 2절에서 따로 본다.

### 규모의 차이

사람 43분으로 3개를 봤다. refscope는 **3.4~4.8분으로 12개**를 봤다.

| | 사람 (3개) | refscope (12개) |
|---|---|---|
| 소요 | 43분 | **3.4~4.8분** |
| 훑은 세로 | 74,634px | **167,088px** |
| 추출 카피 | 13줄 | **300줄** |

같은 3개만 놓고 비교하면 **43분 → 1.2~1.5분, 29~37배**. 카피는 13줄 → 75줄로 **6배**다.
시간만 준 게 아니라, 앞에서 본 "길수록 포기한다" 문제를 없앴다.

## 2. 성공 기준 #4는 왜 미달했나 (47%)

```bash
uv run python -m refscope.score_sections
```

사람이 적은 섹션 15개 중 기계가 맞춘 것 7개 = **47%** (목표 70%).
채점은 bge-m3 코사인 유사도 ≥0.62로 한다 — 사람 "제품사용 Tip"과 기계 "사용법·보관법"은
문자열로는 못 맞추기 때문이다.

| 사이트 | 정확도 |
|---|---|
| 교동한과 만월 | 4/5 (80%) |
| 강릉명일한과 | 2/5 (40%) |
| 한품 99플라워 | 1/5 (20%) |

### 놓친 8개를 뜯어보면

**(a) 세는 단위가 다르다 — 3건.** 사람은 세 사이트 모두 "네비게이터"를 첫 섹션으로 적었다.
기계는 내비게이션 바를 콘텐츠 섹션으로 세지 않는다. 이건 성능 차이가 아니라 정의 차이다.
**내비게이터를 빼면 7/12 = 58%**로 오른다. 그래도 목표에는 못 미친다.

**(b) 분할 입도 차이 — 1건.** 한품 "선물추천"은 기계의 "제품 소개"와 유사도 0.68로
임계값을 넘었지만, 다른 항목이 그 짝을 먼저 가져가서 놓쳤다. 사람은 5개로 나눴고
기계는 5개로 나눴는데 **경계가 어긋난** 경우다.

**(c) 진짜 실패 — 4건.** "히어로 제품, 원산지, 가격정보", "Q&A", "메인 사진, 가격",
"연출샷". 특히 **"연출샷"(유사도 0.44)은 구조적 한계**다. 연출샷은 글자가 거의 없는
구간이라 텍스트 기반 분할로는 잡히지 않는다. 사람은 그림을 보고 "여긴 연출샷 구간"이라고
적었지만, 기계는 좌표에 붙은 글자만 보고 나눴다.

### 그래서 무엇을 해야 하나

섹션 분할은 **텍스트만으로는 안 된다.** ⑤ 갈래에서 "나누기는 좌표, 이름만 LLM"으로
설계한 것이 카피 추출에는 맞았지만 구조 분류에는 부족했다. 개선 방향은 4절에 적었다.

## 3. 실패 사례

퀘스트가 요구한 항목이기도 하지만, 이 목록이 이 PoC에서 가장 값이 나가는 부분이다.
**전부 실제로 겪었고, 대부분 조용히 틀리고 있었다.**

### 3-1. 파이프라인이 404 페이지를 정상 데이터로 삼켰다

첫 수집에서 상세페이지 3개 중 2개가 사실 **오류 페이지**였다.

- 서울쿠키: 900px짜리 카페24 "다시 한번 확인해주세요!" 화면
- 한품: "404를 찾을 수 없음" 페이지

둘 다 **HTTP 200으로 응답한다.** 상태 코드만 봐서는 못 걸러낸다. 그런데 파이프라인은
이것을 "카피가 거의 없는 페이지"로 받아들여 통계에 넣고 있었다.

> 리서치 도구가 오류 화면을 데이터로 세면 **"이 브랜드는 카피가 없다"** 같은 헛된
> 결론이 나온다. 그리고 그건 검증되지 않고 회의 자료가 된다.

**고침**: HTTP 상태 확인 + 200으로 위장한 오류 화면의 문구 감지
([`capture.py`](../src/refscope/capture.py)의 `looks_like_error_page`).

### 3-2. 읽기 경로 판정을 두 번 틀렸다

1. **페이지 단위로 세다 상용구에 속았다** — 통이미지 페이지를 `dom`으로 오판
2. **가로 피복률로 재다 세로로 긴 이미지를 놓쳤다** — 500px 폭이 1,440px의 35%뿐

자세한 내용은 [모델 선정 문서 ②절](02_model_selection.md). 둘 다 **에러 없이 잘못된 답을
내놓고 있었다.** 우연히 개별 페이지를 열어보지 않았다면 그대로 갔을 것이다.

### 3-3. 엔진 격리 전 EasyOCR 재현율을 0%로 잘못 측정했다

PaddleOCR과 EasyOCR을 한 프로세스에서 연달아 돌렸더니 EasyOCR이
`(PreconditionNotMet) Tensor holds no memory` 오류로 전부 죽었다. 표에는 **0%**로 찍혔다.

단독 프로세스에서 돌리니 멀쩡히 동작했고 실제 재현율은 **100%**였다.
하마터면 "EasyOCR은 한국어를 전혀 못 읽는다"고 문서에 쓸 뻔했다.

**고침**: 엔진마다 별도 프로세스([`ocr_worker.py`](../src/refscope/ocr_worker.py)).

### 3-4. 대조군을 파서 결함으로 지게 만들 뻔했다

대조군 B를 처음 돌렸을 때 3개 중 2개가 "카피 0줄"로 나왔다. 순진한 방법이 실패한
것처럼 보였다. 그런데 원문을 열어보니 **모델은 멀쩡히 내용을 냈고**, 다만 `- ` 불릿 대신
맨 줄이나 `1. ` 번호를 썼을 뿐이었다. 내 파서가 `- `만 받고 있었다.

> 대조군을 내 코드 결함 때문에 지게 만들면 **비교 자체가 거짓이 된다.**
> "설계가 만든 차이"라는 이 문서의 핵심 주장이 통째로 무너진다.

**고침**: 세 형식을 모두 받도록 파서 수정 후 **같은 응답을 다시 파싱**해 재채점.
(VLM을 다시 돌리지 않았다 — 같은 출력으로 공정하게 비교하기 위해)

### 3-5. 한국어 OCR은 빈손으로 돌아오지 않는다

EasyOCR 실제 출력:

```
0.04  [유과] 쌀 우미 속 백려조 오냐 녹독자
0.02  [정과] 호두 키위 금곡 대주조관 [강징] 후미 전미 속감- 백런조갑쌀
0.00  [한물곡식] 잠여외무공 돈끼와우공 우꺼와부공 다시마와루미
```

한국어 인식이 무너지면 **그럴듯한 헛것**이 나온다. 글자 수만 세면 EasyOCR이
13,402자로 1등이다. 교차확인 지표(59%)와 저신뢰 비율(29%)을 함께 보지 않았다면
이 엔진을 골랐을 것이다.

Apple Vision도 완벽하지 않다 — 교동한과에서 **"쌈촛촌"** 같은 오독이 있다.
다만 빈도가 낮고 신뢰도가 함께 낮게 나온다.

### 3-6. VLM의 톤 서술이 팔레트와 정면으로 모순됐다

단정(내 사이트) 카드에서:

- **자동 팔레트**: `#1d1a18`, `#070709`, `#3a2921` — 거의 검정
- **VLM 톤 서술**: *"따뜻한 베이지와 흰색의 조화로, 명도 대비가 부드럽게 느껴진다"*

정반대다. 원인은 대조 시트다. 44,491px급 페이지를 폭 300px로 줄여 6등분해 붙이는데,
**어두운 히어로 구간이 축소 과정에서 비중을 잃었다.** VLM은 밝은 하단부만 보고 답했다.

> **같은 페이지에 대해 두 모듈이 반대 결론을 내는데 아무도 이의를 제기하지 않는다.**
> 파이프라인이 서로를 검증하지 않기 때문이다. 이게 현재 구조의 가장 큰 약점이다.

### 3-7. 나누기와 이름 짓기를 함께 시켰더니 되뱉었다

"좌표 붙은 텍스트를 섹션으로 묶어줘"라고 하자 qwen2.5vl:7b는 입력 20줄을
**20개 섹션으로 그대로 되뱉었다.** "5~8개로 묶으라"는 지시를 무시했다.

**고침**: 나누기는 y 간격으로 결정적으로, 이름만 모델에게. 이후 정상 동작.

### 3-8. 무한 스크롤에서 수집이 늘어진다

한품(Shopify)은 스크롤 400회로도 바닥에 닿지 못해 수집에 **99.6초** 걸렸다
(다른 사이트는 4~22초). 경고는 남기지만 근본 해결은 못 했다.

| **무한 스크롤** | 3-8 | 높이 증가가 멈추지 않으면 상한에서 끊고 명시 |
| **평가셋 12개** | 통계적 일반화는 무리 | 카테고리를 넓혀 50개 규모로. 특히 홈:상세 비율 |
| **정답이 3개 사이트뿐** | 사람 시간이 비쌈 | 현재 결론은 "이 3개에서 그랬다" 이상은 아니다 |

### 실제 도입까지 필요한 것

- **데이터**: 추가 비용 없음. 공개 페이지만 보고, 원본은 로컬에만 둔다.
- **비용**: **0원.** 전 단계 로컬 실행이라 API 과금이 없다. 필요한 것은 디스크 약 8GB
  (Ollama 모델)와 M 시리즈 맥.
- **운영**: 프로젝트 착수 시 1회 배치. 실시간 처리가 필요 없어 운영 부담이 거의 없다.
- **가장 큰 리스크**: 이 도구는 **자신 있게 틀릴 수 있다.** 근거율 100%가 "카피를
  안 지어낸다"는 뜻이지 "구조 해석이 맞다"는 뜻은 아니다. 카드는 **판단의 재료**이지
  결론이 아니라는 것을 사용 규칙으로 못박아야 한다.

## 5. 정성 비교 — 무엇이 달라졌나

### 남은 것

사용자가 손으로 적은 교동한과 카피 7줄과 refscope가 뽑은 것을 비교하면,
refscope는 사람이 놓친 것을 잡았다.

| 사람이 적은 것 | refscope가 추가로 잡은 것 |
|---|---|
| 안녕하세요 교동한과입니다 / 교동한과 만월 / 물려주고 싶은 전통의 맛, / 한국 / 정성 / 맛 / 영양 | 고마운 분께 전하는 정성 / 한과의 품격을 담았습니다 / **아트콜라보 프로젝트** / 김경희 작가의 달항아리 작품에 담긴 평안과 행복의 감성을 / 교동한과는 믿을 수 있는 국내산 찹쌀로 / 좋은 곡식으로, 좋은 조화를 |

**"아트콜라보 프로젝트 — 김경희 작가의 달항아리"** 는 브랜드 전략상 중요한 정보인데
사람은 17분을 쓰고도 적지 못했다. 44,491px를 훑는 중에 놓친 것이다.

### 사라진 것

사람의 노트에는 **"차분, 전통 문양"** 같은 한 줄 인상이 있다. refscope의 VLM 톤 서술은
네 문장으로 더 길지만, 3-6에서 봤듯 **틀릴 수 있다.** 사람의 한 줄이 짧아도 신뢰도는 높다.

### 그래서 어떻게 쓰는 것이 맞나

> refscope는 **2~7번(옮겨 적기)을 대신하고, 8번(판단)은 사람에게 남긴다.**
> 카드를 읽고 "그래서 우리가 설 자리는 어디인가"를 정하는 것은 여전히 디자이너의 일이다.
> 다만 이제 지친 상태가 아니라 217줄을 다 본 상태에서 정한다.
>
> *— 커리큘럼 4-8절 「넘긴 것은 노동이고 남은 것은 결정입니다」*

## 6. 추가 시도 — 리서치의 진짜 결론

카드 12장은 아직 재료다. 디자이너가 답해야 하는 질문은 하나다.

> **"이 바닥은 지금 무슨 말을 하고 있고, 아무도 안 하는 말은 무엇인가?"**

```bash
uv run python -m refscope.patterns
```

경쟁·톤 레퍼런스 11곳의 카피 **217줄**을 bge-m3로 임베딩해 8개 소구점으로 묶었다.

그리고 단정의 카피를 같은 공간에 올려 각 소구점과의 거리를 쟀다.

| 소구점 | 단정 최대 유사도 | |
|---|---|---|

### 읽어낸 것

1. **단정은 "감사·마음 전달"에 가장 깊이 들어가 있다** (0.83). B2B 답례 선물 포지션과 일치한다.
2. **"국내산 재료"가 비어 있다** (0.52). 경쟁 5곳이 원산지를 말하는데 단정은 안 한다.
   프리미엄을 표방하면서 재료 출처를 말하지 않는 것은 **설득의 구멍**이다.
3. **"매장·지점"이 비어 있는 것은 의도된 것**이다. 단정은 온라인 B2B라 매장이 없다.
   비어 있다고 다 채워야 하는 게 아니라는 것 — 여기서 판단이 필요하다.

**이 표가 이 PoC의 최종 산출물이다.** 카드 12장이 아니라, 카드에서 나온 이 한 장이
다음 시즌 상세페이지의 카피 방향을 정한다.
