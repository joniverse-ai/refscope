# 문제 정의서 — 강의 녹음 × 강의자료 정렬 노트 생성기

> Main Quest 2 제출물 1/4
> 상태: 초안 (v0.1) — `[측정]` 표시된 값은 베이스라인 측정 후 채운다

---

## 1. 도메인 설명

**말과 문서가 같은 시간에 흐르지만 서로 연결되지 않는 학습·회의 현장.**

구체적으로는 아이펠 과정을 포함한 강의·세미나·스터디 환경이다. 한 세션이 끝나면 산출물이 두 갈래로 남는다.

| 산출물 | 형태 | 특징 |
|---|---|---|
| 녹음 | 30~90분 오디오 1개 | 시간 축은 있지만 구조가 없다 |
| 자료 | 슬라이드 PDF / 이미지 | 구조는 있지만 설명이 없다 |

둘은 같은 사건을 기록한 두 개의 사본인데, **서로를 가리키는 포인터가 없다.**

## 2. 현재의 문제

### 지금의 작업 흐름 (as-is)

1. **수업 중**: 필기를 시도한다 → 말 속도를 못 따라간다 → 자료에 이미 적힌 내용을 중복해서 옮겨 적는다
2. **복습 시**: 자료 PDF를 연다 → 이해가 안 되는 슬라이드를 만난다 → 녹음 파일을 열고 해당 대목을 찾는다
3. **탐색**: 스크럽바를 앞뒤로 왕복한다. 슬라이드 1장의 설명 위치를 찾는 데 평균 `[측정]`분
4. **포기**: 결국 녹음은 대부분 다시 듣지 않는다 → 녹음의 정보 가치가 사실상 0으로 소멸

### 병목의 성격

정보가 부족한 게 아니다. **두 매체가 정렬되어 있지 않아서, 사람이 매번 손으로 정렬 작업을 대행하고 있다.** 이 정렬은 규칙이 단순하고 반복적이다 — 자동화 후보의 교과서적 조건.

## 3. 개선 가설

> 정렬 작업을 AI에 넘긴다. 슬라이드 텍스트와 발화 텍스트를 같은 의미 공간에 올리면, 어떤 발화가 어떤 슬라이드에 속하는지 기계가 배정할 수 있다.

### 파이프라인

```
[오디오]  ──STT(Whisper)──▶  타임스탬프 세그먼트 (start, end, text)
                                          │
[자료PDF] ──페이지 렌더──▶ OCR/VLM ──▶ 페이지별 텍스트
                                          │
                                          ▼
                          임베딩 유사도 + 단조 정렬 제약
                                          │
                                          ▼
                        세그먼트 → 슬라이드 배정 (page_id, [t_start, t_end])
                                          │
                                    LLM 요약·용어·Q&A
                                          │
                                          ▼
        [출력] 슬라이드 썸네일 + 해당 발화 전사 + 타임코드 + 요약이
               한 화면에 붙은 Markdown / HTML 노트
```

### 이 PoC의 핵심 아이디어: 단조 정렬 제약

순수 임베딩 유사도만 쓰면 비슷한 용어가 반복되는 슬라이드에서 배정이 튄다. 하지만 강의는 **대체로 슬라이드 순서대로 진행된다**. 즉 "시간이 흐르면 페이지 번호는 되돌아가지 않는다"는 제약(DTW 계열의 단조성)을 걸 수 있다. 유사도 매칭 단독 대비 이 제약을 넣은 버전의 정확도를 비교하는 것이 실험의 중심이다.

### 커리큘럼과의 연결

| 회차 | 내용 | 이 PoC에서 쓰는 곳 |
|---|---|---|
| 4회차 | OCR 조립 라인, 이미지+언어 모델(VLM) | 슬라이드 텍스트 추출 |
| 6회차 | 소리를 글자로 바꾸는 길 (STT) | 발화 전사 |
| 3회차 | 로컬 vs API, 데이터·비용·통제권 | 실행 위치 결정 (녹음은 민감 데이터) |
| 2회차 | 토큰 예산·컨텍스트 설계 | 1시간 전사를 LLM에 넣는 청킹 전략 |
| 6회차 | 목소리를 만든다 (TTS) | (선택) 요약 오디오 브리핑 |

## 4. 대상 사용자

- **1차 사용자: 나 자신.** 강의를 듣고 복습하는 학습자. (규칙상 대상 사용자가 본인이어도 무방)
- **2차 사용자**: 같은 과정 동료, 세미나 참석자, 회의 녹음과 배포 자료를 대조해야 하는 실무자
- **사용 시점**: 강의 직후 1회 실행(배치) → 복습할 때마다 노트 조회. 실시간 처리는 필요 없다.

## 5. 성공 기준

| 지표 | 기존 방식 | 목표 | 측정 방법 |
|---|---|---|---|
| **슬라이드 정렬 정확도** | 사람이 하면 100%, 단 전량 수작업 | 슬라이드 20장 중 **16장 이상(80%)** 정확 배정 | 내가 만든 정답 타임코드(`labels.csv`)와 비교 |
| **특정 슬라이드 설명 찾는 시간** | `[측정]`분 (스크럽바 탐색) | **10초 이내** (노트에서 타임코드 클릭) | 슬라이드 5장 무작위 선정, 스톱워치 실측 |
| **1강분 노트 제작 시간** | 수기 정리 `[측정]`분 | **5분 이내** (실행 + 검토) | 실측 |
| **전사 품질 (WER)** | — | 5분 구간에서 **10% 이하** | 직접 전사한 정답과 비교 |

**정성 검증**: 슬라이드 3장을 골라 ① 내 수기 필기 ② 녹음 통짜 요약만 한 결과 ③ PoC 노트를 나란히 놓고 무엇이 달라지는지 서술. 실패 사례를 반드시 함께 기록.

## 6. 검증 설계 (구현 전에 못 박아두기)

- **평가셋**: 강의 1~2개, 슬라이드 총 20~30장. 각 슬라이드의 정답 시작 타임코드를 수동으로 기록 → `data/labels.csv`
- **베이스라인은 PoC를 만들기 전에 측정한다.** 만든 뒤에는 기존 방식의 불편을 재현할 수 없다.
- **비교군 3개**
  - (A) 수기 필기 — 기존 방식
  - (B) 녹음 통짜 요약만 (6회차 실습 수준) — 중간 대조군
  - (C) PoC 정렬 노트
- (B)를 대조군으로 두는 이유: "정렬이 실제로 기여했는가"를 분리해서 보여줄 수 있다.

## 7. 범위 밖 (out of scope)
